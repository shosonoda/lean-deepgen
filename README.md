Lean Deepgen is a **Lean 4** formalization of the paper
*Why and When Deep is Better than Shallow: Implementation-Agnostic State-Transition Model of
Deep Learning* ([arXiv:2505.15064](https://arxiv.org/abs/2505.15064)). The paper studies deep
models through an implementation-agnostic *state-transition model*: a hidden layer is a
continuous self-map of a metric state space, the depth-$k$ hidden class is the word ball
$B(k,F)$ of the semigroup generated by a set $F$ of such maps, and the hypothesis class is
$\mathcal{H}_k = H \circ B(k,F)$ for an output-layer class $H$. In this setting the paper proves an
implementation-free bias--variance decomposition of the generalization error, a hidden--output
decomposition of the Rademacher complexity through a Dudley entropy integral, growth conditions
on the hidden semigroup (saturation P1/P1', polynomial growth P2, exponential growth E1/E1'/E2,
super- and double-exponential growth E3) with the resulting variance profiles, the depth
trade-offs they induce, a conditional Sudakov-type lower bound matching the upper bounds, and
worked examples (implementation, readout, chain-of-thought computation, unrolled ODE solvers).
The formalization is built on **Mathlib** and on the learning-theory library
[lean-rademacher](https://github.com/auto-res/lean-rademacher) (`FoML`).

**Start with the [Blueprint](https://shosonoda.github.io/lean-deepgen/blueprint/).**
It is a mathematical guide with definitions, theorem statements, proofs and links to the Lean
code; the [dependency graph](https://shosonoda.github.io/lean-deepgen/blueprint/dep_graph_document.html)
shows what depends on what, and a [PDF version](https://shosonoda.github.io/lean-deepgen/blueprint.pdf)
is available. The [Comparator certificate](https://shosonoda.github.io/lean-deepgen/comparator.html)
records the latest machine check that the paper's theorems are proved from the standard axioms only.

## What is formalized

Every statement of the paper listed below is proved in Lean. The library contains **no `sorry`**,
and the main theorems depend only on the standard axioms `propext`, `Classical.choice` and
`Quot.sound` (checked with `#print axioms` and, independently, by
[Comparator](#comparator-certificate)).

| Paper | Content | Lean modules (`LeanDeepgen/`) | Status |
| --- | --- | --- | --- |
| Sec. 2 | Setting: word balls $B(k,F)$, uniform and empirical metrics $d_\infty$, $d_S$, covering and packing numbers, hypothesis classes and implementation error, bounded Lipschitz losses, risks and $\eta$-empirical minimizers, Rademacher complexity, entropy integral $V_k(S)$, sub-Gaussian increment and readout-realization assumptions | `Setting/WordBall`, `Setting/Metrics`, `Setting/Covering`, `Setting/Hypothesis`, `Setting/Loss`, `Setting/Rademacher`, `Setting/Assumptions`, `Profiles/Defs` | definitions and basic lemmas |
| Sec. 3, Theorem 1 (`thm:bv`, `thm:bv-general`) | Implementation-free bias--variance decomposition (general pseudometric version and the Lipschitz-loss version; also as a uniform gap bound) | `Bounds/BiasVariance` | proved |
| Sec. 3, Theorem 2 (`thm:hidden-decomp`, `prop:hilbert-sg`, `prop:finite-lipschitz-sg`) | Hidden--output decomposition of the empirical Rademacher complexity via Dudley's integral; sub-Gaussian output layers (inner-product readouts, finite Lipschitz classes) | `Bounds/HiddenOutput` | proved |
| Sec. 3, Theorem 3 and Corollary (`thm:sudakov-type`, `cor:sudakov-rates`, `cor:matching`) | Conditional Sudakov-type lower bound and the matching $\sqrt{k/n}$, $\sqrt{\log k/n}$ rates | `Bounds/Sudakov` | proved |
| App. (`thm:rad.decomp.ent.ent`) | Deterministic entropy decomposition (sup-norm and sample versions) | `Bounds/EntropyDecomp`, `Bounds/EntropyDecompSample` | proved |
| Sec. 4 / App., growth conditions | Basic covering lemmas; Arzela--Ascoli for self-maps (`thm:caa`); saturation P1 and P1'; polynomial growth P2; exponential growth E1, E1', E2; memory-preserving expansion E3 with `cor:superexp`, `cor:doubleexp` | `Growth/Defs`, `Growth/Lemmas`, `Growth/ArzelaAscoli`, `Growth/Saturation`, `Growth/Polynomial`, `Growth/Exponential`, `Growth/MemoryExpansion` | proved |
| Sec. 4.2 (`lem:log-split`, `prop:profiles`, `prop:profiles-finite`, table of profiles) | Variance profiles from growth and diameter; the variance term of the table of profiles | `Profiles/LogSplit`, `Profiles/Profiles`, `Bounds/Variance` | proved |
| Sec. 5 (trade-off table) | Bias laws, variance profiles, balancing depths and balanced rates in the four regimes EL, EP, PL, PP (two-sided $\Theta$ statements) | `Tradeoff/Defs`, `Tradeoff/Regimes` | proved |

The library is about 12,000 lines of Lean with about 550 `@[blueprint]` nodes. General-purpose
tools developed for this project live in lean-rademacher, under
[`FoML.ToMathlib`](https://github.com/auto-res/lean-rademacher/tree/main/FoML/ToMathlib) and
[`FoML.ToFoML`](https://github.com/auto-res/lean-rademacher/tree/main/FoML/ToFoML): the
contraction inequality for arbitrary index sets, one-sided uniform deviation bounds, Dudley's
inequality for sub-Gaussian processes on finite probability spaces, a Hilbert-space Hoeffding
(Pinelis-type) tail bound, Gaussian comparison (Sudakov--Fernique, Gaussian Sudakov minoration),
and the Bernoulli--Sudakov minoration, together with covering-number, separability and
integration lemmas aimed at Mathlib.

### Deviations from the printed manuscript

The Lean statements are the manuscript's statements after the corrections found during the
formalization. The main differences are:

- **Integrability of Dudley integrals.** The hidden--output and entropy decompositions assume
  that the entropy integrand is integrable (Lean's Bochner integral of a non-integrable function
  is `0`, so the literal statement would be false).
- **Boundedness of suprema.** Theorem 1 assumes a measurable loss, `b > 0` and pointwise
  boundedness of the hypothesis class; the Sudakov-type bound assumes that the Rademacher
  averages of $\mathcal{H}_k$ are finite (a bounded-class corollary is provided).
- **Explicit constants in Theorem 1.** The bound reads
  $\beta_\ell\,\varepsilon_{\mathrm{imp}} + \varepsilon_{\mathrm{model}} + \eta + 4\beta_\ell \hat R_S(\mathcal{H}_k) + 6b\sqrt{2\log(4/\delta)/n}$
  (gap version: $2\beta_\ell \hat R_S + 3b\sqrt{2\log(4/\delta)/n}$), and the gap bound holds for
  every hypothesis, not only for empirical minimizers.
- **Scale factors in the entropy decomposition.** Covering numbers are taken at radii
  $x/4$ and $x/(8L_H)$ over $[0, B_H/2]$, following the covering-number convention of
  lean-rademacher; the table of profiles passes from $d_S$ to $d_\infty$ through the external
  covering number, which adds a factor $2^D$ to the constant of P2.
- **Adopted generalizations.** Arbitrary anchor $f_0 \in F$ in the hidden--output decomposition;
  real inner-product spaces instead of Hilbert spaces; the Sudakov-type bound for an arbitrary
  hidden subset $B \subseteq C(\mathcal{X},\mathcal{X})$; weaker hypotheses in the growth conditions
  (no compactness in P1 (1), all depths in P1', $k \ge 0$ in P2, freeness dropped in E1, no
  isometry in E1', disjoint chambers in E2, no compactness of $G$ and quantified "small
  $\varepsilon$" in E3); two-sided $\Theta$ trade-off rates with explicit balancing depths (a
  Lambert-W-free depth for PL) and the exact balancing principle for PP; rigorous
  high-probability versions with explicit depths of the chain-of-thought and ODE propositions.
- **Hypotheses instead of citations.** The cited theorems on nilpotent groups (Guivarc'h--Bass,
  Breuillard) are not formalized; P2 takes their conclusion as a hypothesis. The projection of
  the ODE examples is an abstract projection hypothesis, and the gradient-step contraction uses
  strong monotonicity and co-coercivity.

Each blueprint node states its hypotheses in full; consult it when reusing a result.

## Building the Lean project

The project uses Lean `v4.32.0`, pinned by `lean-toolchain`, and the following dependencies,
pinned by `lake-manifest.json`:

| Package | Version | Revision |
| --- | --- | --- |
| [Mathlib](https://github.com/leanprover-community/mathlib4) | `v4.32.0` | `81a5d257c8e410db227a6665ed08f64fea08e997` |
| [LeanArchitect](https://github.com/hanwenzhu/LeanArchitect) | `v4.32.0` | `3810ba48f2e5bbd83b32623d21fc059b279dbf81` |
| [lean-rademacher](https://github.com/auto-res/lean-rademacher) (`FoML`) | `main` | `db9f18714b0b9934553c37db1b41250462dc7faa` |
| [checkdecls](https://github.com/PatrickMassot/checkdecls) | `master` | `3d425859e73fcfbef85b9638c2a91708ef4a22d4` |

Install Lean with [elan](https://github.com/leanprover/elan), then run:

```bash
git clone https://github.com/shosonoda/lean-deepgen.git
cd lean-deepgen
lake exe cache get   # Mathlib build cache
lake build
```

To inspect a statement interactively, open the clone in VS Code with the Lean 4 extension and
create a scratch file, for example:

```lean
import LeanDeepgen.Bounds.BiasVariance

#check LeanDeepgen.bv
#print axioms LeanDeepgen.bv
```

## Blueprint

The blueprint is generated from the Lean sources: every declaration carrying a
[LeanArchitect](https://github.com/hanwenzhu/LeanArchitect) `@[blueprint]` annotation becomes a
node, with its LaTeX statement and proof sketch taken from the annotation and the `\uses`
dependencies inferred from the constants occurring in the statement and proof.

```bash
lake build :blueprint            # extract the LaTeX into .lake/build/blueprint/
pip install -r requirements.txt  # leanblueprint (needs graphviz and pygraphviz)
leanblueprint web                # blueprint/web/
leanblueprint pdf                # blueprint/print/print.pdf (needs TeX Live)
lake exe checkdecls blueprint/lean_decls
```

`./script/generate.sh` runs all of the above (`--no-pdf` skips the PDF, `--serve` starts a local
server) and assembles the project page in `site/`. `blueprint/src/content.tex` holds the chapter
structure and pulls in the extracted nodes with `\inputleanmodule{...}`.

## Comparator certificate

[Comparator](https://github.com/leanprover/comparator) certifies that the paper's theorems are
proved from the standard axioms only. The directory `comparator/` contains:

- `Challenge.lean`: 55 theorems, one per paper label, each stating a result of the paper with
  the proof replaced by `sorry`, importing only the definition modules of the library;
- `Solution.lean`: the same statements proved by the corresponding library theorems;
- `config.json`: the theorem names and the permitted axioms `propext`, `Quot.sound`,
  `Classical.choice`;
- `README.md`: the mapping paper label -> challenge theorem -> library declaration.

Comparator checks that each listed theorem has, in `Solution`, exactly the statement given in
`Challenge` (every constant occurring in the statement is identical in both environments), that
its proof uses only the permitted axioms, and that Lean's kernel accepts the exported solution.

```bash
# once: Comparator and lean4export (for this project's Lean version) in ../comparator-tools/
mkdir -p ../comparator-tools && cd ../comparator-tools
git clone https://github.com/leanprover/comparator.git && (cd comparator && lake build comparator)
git clone --branch v4.32.0 https://github.com/leanprover/lean4export.git lean4export-v4.32.0 && (cd lean4export-v4.32.0 && lake build)
cd -
./script/comparator.sh   # about a minute; the last line should read "Your solution is okay!"
```

The tool locations can be overridden with `COMPARATOR_TOOLS`, `COMPARATOR_BIN`,
`COMPARATOR_LEAN4EXPORT` and `COMPARATOR_LANDRUN` (on Linux, `landrun` is used automatically
when available; otherwise Comparator's `fake-landrun` shim is used). The latest result is
recorded on the [Comparator certificate page](https://shosonoda.github.io/lean-deepgen/comparator.html).

## Repository layout

- `LeanDeepgen/`: the formalization (`Setting`, `Bounds`, `Growth`, `Profiles`, `Tradeoff`, `Examples`)
- `blueprint/src/`: leanblueprint sources (`content.tex`, `web.tex`, `print.tex`, macros)
- `comparator/`: Comparator challenge, solution and configuration
- `home_page/`: the static project page
- `script/`: `generate.sh` (blueprint and site), `comparator.sh`
- `.github/workflows/`: CI (build, blueprint extraction, `checkdecls`) and GitHub Pages deployment
